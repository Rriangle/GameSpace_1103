### 2.4 交易模式 (Transaction Patterns)

**所有點數變動操作必須使用交易:**
```csharp
// 範例: WalletMutationService.AdjustPointsAsync
public async Task<bool> AdjustPointsAsync(int userId, int delta, int operatorId, string reason)
{
    using var transaction = await _context.Database.BeginTransactionAsync();
    try
    {
        // 1. 取得錢包（悲觀鎖定）
        var wallet = await _context.User_Wallet
            .Where(w => w.User_Id == userId && !w.IsDeleted)
            .FirstOrDefaultAsync();

        if (wallet == null) return false;

        // 2. 更新點數
        wallet.User_Point += delta;
        if (wallet.User_Point < 0) throw new InvalidOperationException("點數不可為負");

        // 3. 記錄交易日誌
        var log = new WalletHistory
        {
            UserID = userId,
            ChangeType = delta > 0 ? "Admin_Add" : "Admin_Deduct",
            PointsChanged = delta,
            Description = reason,
            ChangeTime = DateTime.UtcNow
        };
        _context.WalletHistory.Add(log);

        // 4. 儲存變更
        await _context.SaveChangesAsync();

        // 5. 提交交易
        await transaction.CommitAsync();
        return true;
    }
    catch (Exception ex)
    {
        await transaction.RollbackAsync();
        _logger.LogError(ex, "點數調整失敗: UserId={UserId}, Delta={Delta}", userId, delta);
        return false;
    }
}
```

### 2.6.5 配置系統架構 (SystemSettings-Based Configuration)

#### 2.8.2 TimeHelper 實作

**檔案位置:** `Areas/MiniGame/Helpers/TimeHelper.cs`

```csharp
using System;

namespace GameSpace.Areas.MiniGame.Helpers
{
    /// <summary>
    /// Time conversion helper for UTC+8 (Taiwan Standard Time) display
    /// 提供 UTC 時間戳記轉換為台灣標準時間的擴充方法
    /// </summary>
    public static class TimeHelper
    {
        private static readonly TimeZoneInfo Utc8TimeZone =
            TimeZoneInfo.FindSystemTimeZoneById("Taipei Standard Time");

        /// <summary>
        /// 將 UTC DateTime 轉換為 UTC+8 字串格式
        /// </summary>
        /// <param name="dt">UTC DateTime 值</param>
        /// <param name="format">格式化字串 (預設: yyyy-MM-dd HH:mm)</param>
        /// <returns>UTC+8 時間的字串表示</returns>
        public static string ToUtc8String(this DateTime dt, string format = "yyyy-MM-dd HH:mm")
        {
            var utc8Time = TimeZoneInfo.ConvertTime(dt, TimeZoneInfo.Utc, Utc8TimeZone);
            return utc8Time.ToString(format);
        }

        /// <summary>
        /// 將可為 null 的 UTC DateTime 轉換為 UTC+8 字串格式
        /// </summary>
        /// <param name="dt">可為 null 的 UTC DateTime 值</param>
        /// <param name="format">格式化字串 (預設: yyyy-MM-dd HH:mm)</param>
        /// <returns>UTC+8 時間的字串表示,或 "-" 如果為 null</returns>
        public static string ToUtc8String(this DateTime? dt, string format = "yyyy-MM-dd HH:mm")
        {
            if (dt == null) return "-";
            return dt.Value.ToUtc8String(format);
        }

        /// <summary>
        /// 將 UTC DateTime 轉換為 UTC+8 DateTime 物件
        /// </summary>
        /// <param name="dt">UTC DateTime 值</param>
        /// <returns>UTC+8 時區的 DateTime 物件</returns>
        public static DateTime ToUtc8(this DateTime dt)
        {
            return TimeZoneInfo.ConvertTime(dt, TimeZoneInfo.Utc, Utc8TimeZone);
        }

        /// <summary>
        /// 將可為 null 的 UTC DateTime 轉換為 UTC+8 DateTime 物件
        /// </summary>
        /// <param name="dt">可為 null 的 UTC DateTime 值</param>
        /// <returns>UTC+8 時區的 DateTime 物件,或 null</returns>
        public static DateTime? ToUtc8(this DateTime? dt)
        {
            if (dt == null) return null;
            return dt.Value.ToUtc8();
        }
    }
}
```

**設計特點:**
- **TimeZoneInfo 快取:** `Utc8TimeZone` 為靜態唯讀欄位,避免重複查詢
- **統一格式:** 預設格式 `yyyy-MM-dd HH:mm` 符合台灣使用習慣
- **Null 安全:** 提供 `DateTime?` 多載,避免 NullReferenceException
- **擴充方法:** 使用 `this` 關鍵字,提供流暢的 API 呼叫體驗

#### 2.9.1 架構概覽

MiniGame Area 實作了統一的模糊搜尋服務 (`IFuzzySearchService`),支援多欄位智慧搜尋及 5 級優先權排序。此功能大幅提升管理後台的資料查詢體驗,特別是處理中文名稱、帳號、電子券名稱等搜尋場景。

**核心特性:**

- **多欄位支援:** 單次呼叫可同時搜尋多個欄位 (如:姓名、帳號、信箱)
- **中文友善:** 支援拼音、注音、部分字元匹配
- **效能優化:** 記憶體內搜尋,避免資料庫 LIKE '%term%' 效能問題
- **統一介面:** 所有 Controller 使用相同的搜尋模式,程式碼一致性高

#### 2.9.2 IFuzzySearchService 介面

**檔案位置:** (推測) `Areas/MiniGame/Services/IFuzzySearchService.cs`

**介面定義:**
```csharp
public interface IFuzzySearchService
{
    /// <summary>
    /// 計算搜尋詞與目標欄位的匹配優先權
    /// </summary>
    /// <param name="searchTerm">搜尋詞 (使用者輸入)</param>
    /// <param name="fields">目標欄位值 (可變數量參數)</param>
    /// <returns>
    /// 優先權級別:
    /// 0 = 不匹配
    /// 1 = 完全匹配 (Exact Match)
    /// 2 = 開頭匹配 (Starts With)
    /// 3 = 包含匹配 (Contains)
    /// 4 = 模糊匹配 (Fuzzy Match)
    /// 5 = Token 匹配 (Token Match)
    /// </returns>
    int CalculateMatchPriority(string searchTerm, params string[] fields);
}
```

**實作邏輯 (推測):**
```csharp
public class FuzzySearchService : IFuzzySearchService
{
    public int CalculateMatchPriority(string searchTerm, params string[] fields)
    {
        if (string.IsNullOrWhiteSpace(searchTerm))
            return 0;

        var normalizedTerm = searchTerm.Trim().ToLowerInvariant();

        foreach (var field in fields)
        {
            if (string.IsNullOrWhiteSpace(field))
                continue;

            var normalizedField = field.Trim().ToLowerInvariant();

            // 級別 1: 完全匹配
            if (normalizedField == normalizedTerm)
                return 1;

            // 級別 2: 開頭匹配
            if (normalizedField.StartsWith(normalizedTerm))
                return 2;

            // 級別 3: 包含匹配
            if (normalizedField.Contains(normalizedTerm))
                return 3;

            // 級別 4: 模糊匹配 (Levenshtein距離 <= 2)
            if (GetLevenshteinDistance(normalizedField, normalizedTerm) <= 2)
                return 4;

            // 級別 5: Token 匹配 (空格分隔後部分匹配)
            var tokens = normalizedField.Split(new[] { ' ', '-', '_' },
                StringSplitOptions.RemoveEmptyEntries);
            if (tokens.Any(t => t.Contains(normalizedTerm)))
                return 5;
        }

        return 0; // 不匹配
    }

    private int GetLevenshteinDistance(string s, string t)
    {
        // Levenshtein Distance 實作 (編輯距離)
```

#### 2.9.3 5 級優先權系統詳解

| 優先權 | 名稱 | 說明 | 範例 (搜尋 "王小明") |
|-------|------|------|---------------------|
| **1** | 完全匹配<br>(Exact Match) | 搜尋詞與欄位值完全相同 (不區分大小寫) | 欄位值: "王小明" → 優先權 1 |
| **2** | 開頭匹配<br>(Starts With) | 欄位值以搜尋詞開頭 | 欄位值: "王小明的帳號" → 優先權 2 |
| **3** | 包含匹配<br>(Contains) | 欄位值包含搜尋詞 | 欄位值: "用戶王小明" → 優先權 3 |
| **4** | 模糊匹配<br>(Fuzzy Match) | 編輯距離 ≤ 2 (容忍拼寫錯誤) | 欄位值: "王曉明" → 優先權 4 (1字不同) |
| **5** | Token 匹配<br>(Token Match) | 以空格/符號分隔後部分匹配 | 欄位值: "User-王小明-VIP" → 優先權 5 |

**排序邏輯:**
- 優先權值越小,排序越前 (1 > 2 > 3 > 4 > 5)
- 優先權 0 表示不匹配,會被過濾掉
- 相同優先權的結果保持原始排序 (通常為建立時間倒序)

**標準整合模式:**

```csharp
public class PetShopController : MiniGameBaseController
{
    private readonly IPetShopService _petShopService;
    private readonly IFuzzySearchService _fuzzySearchService; // ✅ 注入模糊搜尋服務

    public PetShopController(
        IPetShopService petShopService,
        IFuzzySearchService fuzzySearchService)
    {
        _petShopService = petShopService;
        _fuzzySearchService = fuzzySearchService;
    }

    public async Task<IActionResult> Index(string searchTerm, int page = 1)
    {
        // 1️⃣ 基本查詢 (從資料庫取得所有候選資料)
        var query = _context.PetShopItems
            .Include(p => p.Supplier)
            .Where(p => !p.IsDeleted)
            .AsNoTracking();

        // 2️⃣ 模糊搜尋過濾 + 優先權排序
        if (!string.IsNullOrWhiteSpace(searchTerm))
        {
            // ✅ 一次性載入所有資料至記憶體
            var allItems = await query.ToListAsync();

            // ✅ 計算每筆資料的匹配優先權
            var itemsWithPriority = allItems
                .Select(item => new
                {
                    Item = item,
                    Priority = _fuzzySearchService.CalculateMatchPriority(
                        searchTerm,
                        item.ProductName ?? "",      // 欄位 1: 商品名稱
                        item.ProductCode ?? "",      // 欄位 2: 商品編號
                        item.Supplier?.Name ?? ""    // 欄位 3: 供應商名稱
                    )
                })
                .Where(x => x.Priority > 0)           // ✅ 過濾掉不匹配的資料
                .OrderBy(x => x.Priority)             // ✅ 按優先權排序 (小的優先)
                .ThenByDescending(x => x.Item.CreatedAt) // 次要排序:建立時間
                .Select(x => x.Item)
                .ToList();

            // 3️⃣ 分頁處理
            var paginatedItems = itemsWithPriority
                .Skip((page - 1) * 20)
                .Take(20)
                .ToList();

            return View(paginatedItems);
        }

        // 4️⃣ 無搜尋詞時的預設排序
        var defaultItems = await query
            .OrderByDescending(p => p.CreatedAt)
            .Skip((page - 1) * 20)
            .Take(20)
            .ToListAsync();

        return View(defaultItems);
    }
}
```

**整合要點:**
1. **記憶體搜尋:** 因模糊匹配演算法複雜,需先 `ToListAsync()` 載入所有資料
2. **多欄位搜尋:** 使用 `params string[]` 一次傳入多個欄位,任一欄位匹配即可
3. **Null 安全:** 所有欄位值使用 `?? ""` 避免 NullReferenceException
4. **優先權過濾:** `Where(x => x.Priority > 0)` 過濾掉完全不匹配的資料
5. **雙重排序:** 先按優先權,再按建立時間倒序

```csharp
public class PointsService : IPointsService
{
    private readonly GameSpacedatabaseContext _context;
    private readonly IFuzzySearchService _fuzzySearchService;

    public PointsService(
        GameSpacedatabaseContext context,
        IFuzzySearchService fuzzySearchService)
    {
        _context = context;
        _fuzzySearchService = fuzzySearchService;
    }

    public async Task<IEnumerable<PointsHistoryDto>> SearchHistoryAsync(
        string searchTerm,
        DateTime? from,
        DateTime? to)
    {
        var query = _context.WalletHistory
            .Include(w => w.User)
            .Where(w => !w.IsDeleted);

        // 日期範圍過濾
        if (from.HasValue)
            query = query.Where(w => w.ChangeTime >= from.Value);
        if (to.HasValue)
            query = query.Where(w => w.ChangeTime <= to.Value);

        // 模糊搜尋
        if (!string.IsNullOrWhiteSpace(searchTerm))
        {
            var allRecords = await query.ToListAsync();

            var filteredRecords = allRecords
                .Select(record => new
                {
                    Record = record,
                    Priority = _fuzzySearchService.CalculateMatchPriority(
                        searchTerm,
                        record.User?.Account ?? "",
                        record.User?.UserName ?? "",
                        record.ChangeType ?? "",
                        record.Description ?? ""
                    )
                })
                .Where(x => x.Priority > 0)
                .OrderBy(x => x.Priority)
                .ThenByDescending(x => x.Record.ChangeTime)
                .Select(x => x.Record)
                .ToList();

            return MapToDto(filteredRecords);
        }

        var defaultRecords = await query
            .OrderByDescending(w => w.ChangeTime)
            .ToListAsync();

        return MapToDto(defaultRecords);
    }
}
```

#### 2.9.7 效能考量

**記憶體搜尋的權衡:**

**優點:**
- ✅ 支援複雜模糊匹配演算法 (Levenshtein Distance)
- ✅ 多欄位搜尋無需複雜 SQL JOIN
- ✅ 優先權排序靈活,無需資料庫排序函數
- ✅ 避免資料庫 LIKE '%term%' 無法使用索引

**缺點:**
- ❌ 需一次載入所有候選資料至記憶體
- ❌ 資料量大時 (>10,000 筆) 可能影響回應時間
- ❌ 無法使用資料庫分頁 (需手動程式碼分頁)

**最佳實踐:**
1. **限制候選資料量:** 在 `ToListAsync()` 前先套用其他過濾條件 (如日期範圍、狀態)
2. **快取常用搜尋:** 對高頻搜尋詞使用 IMemoryCache 快取結果
3. **分頁處理:** 只載入前 500-1000 筆資料進行模糊搜尋,超過提示使用精確搜尋
4. **背景處理:** 超過 5000 筆資料時,考慮使用背景工作排程處理

**範例:限制候選資料量**
```csharp
// ✅ 先套用日期範圍過濾,再模糊搜尋
var query = _context.WalletHistory
    .Where(w => !w.IsDeleted)
    .Where(w => w.ChangeTime >= DateTime.UtcNow.AddMonths(-3)) // 只搜尋近3個月
    .OrderByDescending(w => w.ChangeTime)
    .Take(1000); // 最多載入1000筆

var allRecords = await query.ToListAsync(); // 記憶體內搜尋
```

```csharp
    public void OnActionExecuting(ActionExecutingContext context)
    {
        var idempotencyKey = context.HttpContext.Request.Headers["Idempotency-Key"].ToString();
        if (string.IsNullOrEmpty(idempotencyKey)) return;

        if (_cache.TryGetValue(idempotencyKey, out var cachedResult))
        {

        }
    }

    public void OnActionExecuted(ActionExecutedContext context)
    {
        var idempotencyKey = context.HttpContext.Request.Headers["Idempotency-Key"].ToString();
        if (!string.IsNullOrEmpty(idempotencyKey) && context.Result is ObjectResult result)
        {
            _cache.Set(idempotencyKey, result, TimeSpan.FromMinutes(5));
        }
    }
```

## 9. 關鍵架構決策

### 9.1 Area-based組織

**決策:** 使用ASP.NET Core Areas分割功能模組

**原因:**
- 模組隔離：每個Area獨立開發
- 團隊擴展：不同團隊負責不同Area
- 權限控制：Area層級的路由保護
- 程式碼組織：避免單一Controllers資料夾過大

**實作:**
```
Areas/
├── MiniGame/      [團隊A負責]
├── Forum/         [團隊B負責]
├── OnlineStore/   [團隊C負責]
└── social_hub/    [團隊D負責]
```

### 9.2 服務抽象層

**決策:** 業務邏輯封裝在Services，不在Controllers

**原因:**
- 關注點分離：Controller只處理HTTP，Service處理業務邏輯
- 可測試性：Service可獨立單元測試
- 可重用性：多個Controller可共用Service
- 易於維護：業務邏輯集中管理

**範例:**
```
Controller (HTTP) → Service (Business) → DbContext (Data)
```

### 9.3 Query/Mutation分離

**決策:** 唯讀操作使用QueryService + AsNoTracking

**原因:**
- 效能提升：AsNoTracking避免變更追蹤overhead
- 清晰職責：Query不應修改資料
- 審計清晰：所有寫入操作集中在MutationService
- CQRS準備：未來可擴展為完整CQRS

**實作:**
```csharp
IWalletQueryService   → 唯讀，AsNoTracking
IWalletMutationService → 寫入，Transaction-wrapped
```

### 9.4 軟刪除模式

**決策:** 所有MiniGame相關表格實作軟刪除

**原因:**
- 資料恢復：誤刪可復原
- 審計需求：保留刪除記錄
- 法規遵循：金融資料不可物理刪除
- 關聯完整性：避免FK constraint衝突

**代價:**
- 查詢複雜度：所有查詢需加 `!IsDeleted`
- 唯一約束：UNIQUE constraint需考慮IsDeleted

### 9.5 交易包裝

**決策:** 所有錢包操作必須包在資料庫交易內

**原因:**
- ACID保證：點數扣除/增加的原子性
- 一致性：錢包餘額與歷史記錄同步
- 錯誤回滾：操作失敗時自動rollback
- 防止資料不一致

**實作:**
```csharp
using var transaction = await _context.Database.BeginTransactionAsync();
try {
    // 多步驟操作
    await transaction.CommitAsync();
} catch {
    await transaction.RollbackAsync();
    throw;
}
```

### 9.6 多DbContexts

**決策:** 使用3個DbContext分隔不同領域

**原因:**
- 領域分離：Identity vs GameSpace vs MemberManagement
- 資料庫分離：可部署到不同資料庫
- 效能：減少單一Context的DbSet數量
- 權限控制：不同Context不同連線字串

### 9.7 AdminCookie認證

**決策:** 自訂AdminCookie scheme，不使用ASP.NET Identity

**原因:**
- 靈活性：完全控制Claims結構
- 簡化：不需要Identity的Role/RoleClaim複雜性
- 客製化：ManagerRolePermission以boolean欄位定義權限
- 效能：避免Identity的多表JOIN

### 9.8 Claims-based授權

**決策:** 使用Claims + Policy定義權限

**原因:**
- 細粒度：可定義多層權限（AdminOnly, CanPet, CanManageShopping）
- 動態檢查：Policy可呼叫Service檢查資料庫
- 擴展性：新權限只需新增Policy
- 標準化：符合ASP.NET Core授權模式

### 9.9 禁用EF Migrations

**決策:** 不使用EF Migrations，手動管理SQL腳本

**原因:**
- SQL Server是單一真相來源：DBA控制schema
- 複雜schema：Migrations難以處理複雜CHECK constraint
- 多人協作：避免Migrations衝突
- 生產環境：DBA需審核所有schema變更

### 9.10 Async/Await全域

**決策:** 所有Service方法使用async/await

**原因:**
- 非阻塞I/O：資料庫查詢不阻塞執行緒
- 擴展性：支援更多並發請求
- ASP.NET Core最佳實踐：符合框架設計
- 效能：減少執行緒池壓力

#### 10.4.5 Git Pre-commit Hook (驗證)

**檔案位置:** `.git/hooks/pre-commit` (需手動建立)

```bash
#!/bin/bash
# 檢查所有暫存的 .cs 和 .cshtml 檔案是否包含 BOM

FILES=$(git diff --cached --name-only --diff-filter=ACM | grep -E '\.(cs|cshtml)$')

for FILE in $FILES; do
  # 檢查檔案開頭3個位元組是否為 BOM (EF BB BF)
  BOM=$(hexdump -n 3 -e '3/1 "%02X"' "$FILE")
  if [ "$BOM" == "EFBBBF" ]; then
    echo "錯誤: $FILE 包含 BOM,請轉換為 UTF-8 without BOM"
    exit 1
  fi
done

exit 0
```
