## 1. 執行摘要（聚焦 Vue + Unity）

### 1.1 技術棧定位

本專案在**維持 ASP.NET Core MVC 架構**的前提下，透過 **Progressive Enhancement** 方式導入現代前端技術：

| 技術 | 用途 | 導入方式 |
|------|------|----------|
| **Vue.js 3** | UI 互動元件化（錢包指標、寵物屬性條、簽到日曆、遊戲入口） | CDN / Area 區域打包 (零越界) |
| **Unity WebGL** | 寵物互動場景 + 寵物冒險小遊戲 | Build 產出置於 Area wwwroot (零越界) |
| **Razor Views** | 伺服器端渲染骨架，SEO 友善 | MVC 預設模式 |
| **ASP.NET Core API** | Area 專屬 RESTful 端點 | ApiController 模式 |
| **React Query / SWR** | 配置快取與自動刷新 | CDN 或 npm 套件 (零越界) |
| **localStorage** | 離線配置備份 | 瀏覽器原生 API |

**核心原則:**
- **非整站 SPA**：每個頁面仍由 MVC Controller Action 提供 Razor View
- **漸進式增強**：初始 HTML 可用，Vue 掛載後增強互動性
- **零越界限制**：所有新增檔案必須位於 `~/GamiPort/GamiPort/Areas/MiniGame/**`
- **最小侵入性**：不修改全域 `Program.cs`、`wwwroot/` 或其他 Areas

### 1.2 完全零越界方案（預設路線）

**方案 A：CDN + Area 區域資源**

| 元件 | 位置 | 說明 |
|------|------|------|
| Vue.js 3 Runtime | CDN (`unpkg.com` 或 `cdn.jsdelivr.net`) | 透過 `<script>` 標籤載入 |
| Vue 組件 | `~/GamiPort/GamiPort/Areas/MiniGame/wwwroot/js/vue-components/**` | ESM 模組或 IIFE 格式 |
| Unity WebGL Build | `~/GamiPort/GamiPort/Areas/MiniGame/wwwroot/unity/PetInteraction/Build/**` | 完整 Build 資料夾 |
| Unity WebGL Build | `~/GamiPort/GamiPort/Areas/MiniGame/wwwroot/unity/PetAdventure/Build/**` | 完整 Build 資料夾 |
| Area 靜態檔設定 | `Areas/MiniGame/Controllers/AssetsController.cs` (可選) | 串流 `.wasm` / `.data.br` |
| API 端點 | `Areas/MiniGame/ApiControllers/**` | Area 專屬 API |
| Service 層 | `Areas/MiniGame/Services/**` | 業務邏輯封裝 |

**優點:**
- ✅ 完全不觸及 Area 外檔案
- ✅ 開發環境即可驗證
- ✅ 部署簡單，無需 Node.js 環境
- ✅ 團隊成員不會衝突

**缺點:**
- ⚠️ CDN 可能受網路環境影響
- ⚠️ 無法使用 `.vue` SFC (Single File Components)
- ⚠️ Unity `.wasm` 需特殊 MIME type（見 pause-and-ask 方案）

### 1.3 可能需要越界的最佳化選項（僅提案，不執行）

**方案 B：區域化 Vite 子專案**

```
~/GamiPort/GamiPort/Areas/MiniGame/
├── _frontend/                          # Vite 子專案 (需額外設定)
│   ├── package.json
│   ├── vite.config.js
│   ├── src/
│   │   ├── components/                # .vue SFC 組件
│   │   └── main.js
│   └── dist/ -> 輸出至 ../wwwroot/js/minigame-dist/
└── wwwroot/
    └── js/
        └── minigame-dist/              # Vite 產出
```

**觸發越界原因:**
1. **Build Script 整合**：需修改專案根 `package.json` 或 `.csproj` 的 `<Target>` 觸發 Vite build
2. **開發伺服器 Proxy**：Vite dev server (port 5173) 需與 ASP.NET Core (port 7160) 整合，可能需要 `Program.cs` 設定 CORS/Proxy

**處理方式:**
- **進入 pause-and-ask 模式**（見第 8 節）
- 提供兩個方案比較：
  - 方案 A：純手動執行 `npm run build`，產出複製至 wwwroot（零越界）
  - 方案 B：自動化整合（需修改 `.csproj` 或 `Program.cs`）

#### 2.1.5 簽到日曆組件（SignInCalendar.js）

```javascript
// ~/GamiPort/GamiPort/Areas/MiniGame/wwwroot/js/vue-components/SignInCalendar.js

export const SignInCalendar = {
    props: {
        year: Number,
        month: Number,
        userId: Number
    },
    data() {
        return {
            days: [],
            loading: true
        };
    },
    computed: {
        firstDayOfWeek() {
            return new Date(this.year, this.month - 1, 1).getDay();
        },
        daysInMonth() {
            return new Date(this.year, this.month, 0).getDate();
        },
        calendarDays() {
            const result = [];

            // 補空白
            for (let i = 0; i < this.firstDayOfWeek; i++) {
                result.push({ empty: true });
            }

            // 實際日期
            for (let day = 1; day <= this.daysInMonth; day++) {
                const dayData = this.days.find(d => d.day === day);
                result.push({
                    day,
                    isSignedIn: dayData?.isSignedIn || false,
                    isToday: this.isToday(day),
                    pointsGained: dayData?.pointsGained || 0
                });
            }

            return result;
        }
    },
    methods: {
        isToday(day) {
            const now = new Date();
            return this.year === now.getFullYear()
                && this.month === now.getMonth() + 1
                && day === now.getDate();
        },
        async fetchCalendar() {
            this.loading = true;
            const response = await fetch(
                `/MiniGame/SignIn/Calendar?year=${this.year}&month=${this.month}`
            );
            this.days = await response.json();
            this.loading = false;
        }
    },
    mounted() {
        this.fetchCalendar();
    },
    template: `
        <div class="calendar-widget">
            <div class="calendar-header">
                <button @click="$emit('prev-month')" class="btn btn-sm btn-outline-primary">
                    <i class="bi bi-chevron-left"></i>
                </button>
                <span class="calendar-title">{{ year }} 年 {{ month.toString().padStart(2, '0') }} 月</span>
                <button @click="$emit('next-month')" class="btn btn-sm btn-outline-primary">
                    <i class="bi bi-chevron-right"></i>
                </button>
            </div>

            <div class="calendar-weekdays">
                <div v-for="day in ['日', '一', '二', '三', '四', '五', '六']" :key="day" class="weekday">
                    {{ day }}
                </div>
            </div>

            <div v-if="loading" class="text-center py-4">
                <div class="spinner-border text-primary" role="status"></div>
            </div>

            <div v-else class="calendar-grid">
                <div v-for="(item, index) in calendarDays"
                     :key="index"
                     class="calendar-day"
                     :class="{
                         'calendar-day-empty': item.empty,
                         'signed-in': item.isSignedIn,
                         'today': item.isToday
                     }"
                     :title="item.isSignedIn ? \`已簽到 (+\${item.pointsGained}點)\` : ''">
                    {{ item.day || '' }}
                </div>
            </div>
        </div>
    `
};
```

#### 2.2.3 觸發越界原因與 pause-and-ask

**情境 1：開發時期 HMR (Hot Module Replacement)**

- Vite dev server 跑在 `http://localhost:5173`
- ASP.NET Core 跑在 `https://localhost:7160`
- 需要在 Razor View 中條件式載入：

```html
@if (Environment.IsDevelopment())
{
    <!-- Vite Dev Server -->
    <script type="module" src="http://localhost:5173/@vite/client"></script>
    <script type="module" src="http://localhost:5173/src/apps/wallet.js"></script>
}
else
{
    <!-- Production Build -->
    <script type="module" src="~/js/minigame-dist/wallet.js"></script>
}
```

**問題：** CORS 錯誤（跨來源）

**零越界替代方案（方案 A）：**
- 不使用 HMR，直接在 `_frontend/` 執行 `npm run build`
- 手動 F5 重新載入頁面驗證

**越界方案（方案 B - 需 pause-and-ask）：**
- 修改 `Program.cs` 加入 CORS 設定：

```csharp
// ⚠️ 需修改專案根 Program.cs（越界）
builder.Services.AddCors(options =>
{
    options.AddPolicy("ViteDevServer", policy =>
    {
        policy.WithOrigins("http://localhost:5173")
              .AllowAnyHeader()
              .AllowAnyMethod();
    });
});

// ...

if (app.Environment.IsDevelopment())
{
    app.UseCors("ViteDevServer");
}
```

**處理：** 進入 **pause-and-ask 模式**（見第 8 節），提供完整 diff 與方案比較。

### 2.3 MVC 對接模式

#### 2.3.1 資料流向

```
Server (Razor) → data-* attributes → Vue 讀取
         ↓
    ViewModel → JSON serialize → <script>window.__INITIAL_DATA__</script>
         ↓
    Vue App 掛載 → mount('#app') → 讀取初始資料
         ↓
    用戶互動 → Vue emits event → fetch API
         ↓
    Area API Controller → Service → Database
         ↓
    JSON Response → Vue 更新 state → UI 重新渲染
```

#### 2.3.2 進階：使用 JSON 序列化注入


### 3.4 MIME/壓縮問題與 pause-and-ask

#### 3.4.1 問題描述

Unity WebGL 產生的 `.wasm.br` 和 `.data.br` 檔案需要正確的 MIME type 與 `Content-Encoding` header：

- `.wasm` → `Content-Type: application/wasm`
- `.br` → `Content-Encoding: br`
- `.gz` → `Content-Encoding: gzip`

ASP.NET Core 預設靜態檔案中介層 **不會** 自動設定這些 header。

#### 3.4.2 零越界替代方案（方案 A）

**建立 AssetsController 串流檔案：**

```csharp
// ~/GamiPort/GamiPort/Areas/MiniGame/Controllers/AssetsController.cs

using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.StaticFiles;

namespace GamiPort.Areas.MiniGame.Controllers;

[Area("MiniGame")]
public class AssetsController : Controller
{
    private readonly IWebHostEnvironment _env;
    private readonly FileExtensionContentTypeProvider _contentTypeProvider;

    public AssetsController(IWebHostEnvironment env)
    {
        _env = env;
        _contentTypeProvider = new FileExtensionContentTypeProvider();

        // 註冊 WASM MIME type
        if (!_contentTypeProvider.Mappings.ContainsKey(".wasm"))
        {
            _contentTypeProvider.Mappings[".wasm"] = "application/wasm";
        }
    }

    // GET: /MiniGame/Assets/Unity/{game}/{*file}
    [HttpGet("Assets/Unity/{game}/{*file}")]
    public IActionResult UnityFile(string game, string file)
    {
        // 安全檢查：防止目錄穿越
        if (file.Contains("..") || game.Contains(".."))
        {
            return BadRequest();
        }

        var areaRoot = Path.Combine(_env.WebRootPath, "Areas", "MiniGame", "wwwroot");
        var filePath = Path.Combine(areaRoot, "unity", game, "Build", file);

        if (!System.IO.File.Exists(filePath))
        {
            return NotFound();
        }

        // 判斷 Content-Type
        _contentTypeProvider.TryGetContentType(filePath, out var contentType);
        contentType ??= "application/octet-stream";

        // 判斷 Content-Encoding
        var fileExtension = Path.GetExtension(filePath);
        string? contentEncoding = null;

        if (fileExtension == ".br")
        {
            contentEncoding = "br";
            // 移除 .br 取得原始檔案類型
            var originalFile = Path.GetFileNameWithoutExtension(filePath);
            _contentTypeProvider.TryGetContentType(originalFile, out contentType);
        }
        else if (fileExtension == ".gz")
        {
            contentEncoding = "gzip";
            var originalFile = Path.GetFileNameWithoutExtension(filePath);
            _contentTypeProvider.TryGetContentType(originalFile, out contentType);
        }

        var fileStream = System.IO.File.OpenRead(filePath);

        // 設定 Response Headers
        if (contentEncoding != null)
        {
            Response.Headers.Add("Content-Encoding", contentEncoding);
        }

        Response.Headers.Add("Cache-Control", "public, max-age=31536000"); // 1 year

        return File(fileStream, contentType ?? "application/octet-stream", enableRangeProcessing: true);
    }
}
```

```csharp
provider.Mappings[".br"] = "application/octet-stream";
provider.Mappings[".data"] = "application/octet-stream";

app.UseStaticFiles(new StaticFileOptions

    ContentTypeProvider = provider,
    OnPrepareResponse = ctx =>
    {
        var file = ctx.File.Name;

        if (file.EndsWith(".br"))
        {
            ctx.Context.Response.Headers.Add("Content-Encoding", "br");
        }
        else if (file.EndsWith(".gz"))
        {
            ctx.Context.Response.Headers.Add("Content-Encoding", "gzip");

        // 長期快取
        if (file.EndsWith(".wasm") || file.EndsWith(".data") || file.EndsWith(".br"))
        {
            ctx.Context.Response.Headers.Add("Cache-Control", "public, max-age=31536000");
        }
    }
});
```

```csharp
namespace GamiPort.Areas.MiniGame.ApiControllers;

{

    private readonly IAppCurrentUser _currentUser;

        IWalletService walletService,

    /// GET: /api/MiniGame/Wallet

        var userId = await _currentUser.GetUserIdAsync(ct);

        if (userId == 0)
        {
            return Unauthorized(new { message = "請先登入" });
        }

        var wallet = await _walletService.GetWalletAsync(userId, ct);
        return Ok(wallet);
    }

    /// POST: /api/MiniGame/Wallet/Change
    /// 變更點數（內部使用，需驗證權限）
    /// </summary>
    [HttpPost("Change")]
    [ValidateAntiForgeryToken]
    [ProducesResponseType(StatusCodes.Status200OK)]
    [ProducesResponseType(StatusCodes.Status400BadRequest)]
    public async Task<IActionResult> Change([FromBody] ChangePointsRequest request, CancellationToken ct)
    {
        var userId = await _currentUser.GetUserIdAsync(ct);

        if (request.Amount == 0)
        {
            return BadRequest(new { message = "金額不可為 0" });
        }

        try
        {
            var success = await _walletService.ChangePointsAsync(
                userId,
                request.Amount,
                request.Reason,
                ct);

            if (success)
            {
                return Ok(new { message = "點數已更新", newBalance = await _walletService.GetPointBalanceAsync(userId, ct) });
            }

            return BadRequest(new { message = "點數不足或操作失敗" });
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "變更點數失敗: UserId={UserId}, Amount={Amount}", userId, request.Amount);
            return StatusCode(500, new { message = "伺服器錯誤" });
        }
    }
}
```

### 4.2 HTTP 錯誤碼語意

| 狀態碼 | 意義 | 使用場景 |
|--------|------|----------|
| **200 OK** | 成功 | 正常查詢、操作成功 |
| **201 Created** | 已建立 | 新增資源（如新增優惠券） |
| **400 Bad Request** | 錯誤請求 | 參數驗證失敗、金額為負數 |
| **401 Unauthorized** | 未授權 | 未登入或 Token 過期 |
| **403 Forbidden** | 禁止訪問 | 權限不足（如試圖修改他人寵物） |

| **409 Conflict** | 衝突 | 今日已簽到、超過每日遊戲次數 |
| **500 Internal Server Error** | 伺服器錯誤 | 資料庫異常、未預期的錯誤 |

### 4.5 前端檔案編碼標準 (2025-11-04 新增)

**所有前端檔案必須使用 UTF-8 without BOM 編碼，以確保與後台編碼標準一致。**

#### 4.5.1 編碼規範

**強制要求：UTF-8 without BOM**

所有 MiniGame Area 前端檔案必須使用 **UTF-8 without BOM** (無位元組順序標記) 編碼：

| 檔案類型 | 編碼要求 | 說明 |
|---------|---------|------|
| `.vue` | UTF-8 without BOM | Vue 單檔案組件 |
| `.js` | UTF-8 without BOM | JavaScript 模組與腳本 |
| `.ts` | UTF-8 without BOM | TypeScript 檔案 |
| `.html` | UTF-8 without BOM | HTML 範本檔案 |
| `.css` | UTF-8 without BOM | 樣式表檔案 |
| `.cshtml` | UTF-8 without BOM | Razor 視圖檔案 |
| `.json` | UTF-8 without BOM | JSON 設定檔 |

**後台檔案對照 (已實施):**
- 後台所有 `.cs` 和 `.cshtml` 檔案已統一使用 UTF-8 without BOM (commit cc81d70)
- 前端應遵循相同標準，確保跨專案編碼一致性

#### 4.5.2 為什麼使用 UTF-8 without BOM？

**技術原因:**

1. **跨平台相容性**
   - BOM (Byte Order Mark) 在 Unix/Linux 系統可能造成解析問題
   - 某些編譯器和工具無法正確處理 BOM
   - UTF-8 without BOM 是現代 Web 開發標準

2. **避免編碼衝突**
   - BOM 可能導致 JavaScript 解析錯誤
   - HTTP 回應標頭可能包含額外的 BOM 字元
   - 影響檔案雜湊值計算 (Git, CI/CD)

3. **Vue.js 和 Unity 相容性**
   - Vue CLI/Vite 預設使用 UTF-8 without BOM
   - Unity WebGL Build 輸出檔案使用 UTF-8 without BOM
   - 確保 JavaScript ↔ Unity 通訊正確編碼

4. **與後台一致性**
   - 後台 GameSpace 已全面採用 UTF-8 without BOM
   - 統一編碼標準降低維護成本
   - 避免前後端整合時的編碼問題

### 7.2 風險識別與零越界替代方案

#### 風險 1：Unity `.wasm` MIME Type 問題

**風險描述：**
瀏覽器可能拒絕載入 `application/octet-stream` 的 `.wasm` 檔案。

**越界方案（需 pause-and-ask）：**
修改 `Program.cs` 全域靜態檔案設定。

**零越界替代方案（預設）：**
使用 `AssetsController` 串流檔案並手動設定 `Content-Type: application/wasm`（見第 3.4.2 節）。

**回退計畫：**
若 AssetsController 效能不佳，再提出 pause-and-ask 申請修改 `Program.cs`。

---

#### 風險 2：Vite Dev Server CORS 問題

**風險描述：**
開發時期 Vite HMR 跨來源請求被 ASP.NET Core 阻擋。

**越界方案（需 pause-and-ask）：**
修改 `Program.cs` 加入 CORS 設定（見第 2.2.3 節）。

**零越界替代方案（預設）：**
不使用 HMR，改為手動執行 `npm run build` 並 F5 重新載入頁面。

**回退計畫：**
若開發效率嚴重受影響，再提出 pause-and-ask 申請。

---

#### 風險 3：Unity 檔案體積過大

**風險描述：**
Unity WebGL Build 產出可能超過 20MB，影響載入速度。

**緩解措施：**
- 啟用 Brotli 壓縮（可減少 60-70% 體積）
- Unity Build Settings 選擇 `Faster (smaller) builds`
- 使用 Asset Bundle 延遲載入非必要資源
- CDN 加速（需全域設定，可能觸發越界）

**零越界替代方案：**
透過 AssetsController 設定 `Cache-Control: public, max-age=31536000`，瀏覽器快取 1 年。

---

#### 風險 4：移動裝置 Unity 效能不佳

**風險描述：**
Unity WebGL 在低階手機上可能卡頓或崩潰。

**緩解措施：**
- Unity 場景降低多邊形數量
- 降低材質解析度
- 限制粒子系統數量
- 提供「低畫質模式」選項

**回退計畫：**
若移動端無法穩定運行，改為桌面端專屬功能（手機顯示「請使用電腦瀏覽」）。
